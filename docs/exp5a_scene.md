## 5. 那 16 个面到底在哪(实测,不是看图)

用户看图的印象是"红线跑出图外了,那里补个虚拟障碍就行"。**判据是对的,位置是错的。**
`classify()`(IK → 限位 → 碰撞)逐点复查 16 个失败面心:

```
y ∈ [0.58116, 0.64118]        全部落在 [0,1] 内,没有一个在页外
θ ∈ [-3.12105, -3.04969]      全部贴着 θ = -π 接缝
16 个里 15 个是**真正有效**的姿态(第 16 个是 collision)
y 在 [0,1] 外的:0 / 16
```

红线"看起来"出图,是因为它是一条**绕环**,沿着 θ=±π 接缝跑 ——
不是离开定义域。所以**虚拟障碍在这里不合法**:虚拟带只在**任务外**
(y<0、y>1,图上的灰带,IJRR Fig. 5)才成立;把 y≈0.6 处真实可达、
无碰撞的姿态宣布为无效,证的就是另一个问题了。

**但"只要墙不落进有效区就行"这个判据本身完全正确**,而且差得极小。
对每个失败面心的 y 二分求真实有效集边界:

| 量 | 值 |
|---|---|
| 真实有效集边界 | θ ≈ **−3.1212** |
| 面心 − 真实边界 | **+0.00015 … +0.062 rad** |
| 折算成一个网格格 (0.157 rad) | **0.001 … 0.395**,均值 0.17 |
| 全部在一个格之内? | **True** |

墙不是在自由空间里乱走,它是在**贴着接缝的限位带走,欠了不到半个格** ——
因为 SVM **从没见过那条边界**:网格 θ 只采到 −3.1416(无效)与 −2.9845(有效),
真实边界 −3.1212 落在两者之间的空档里。

## 6. 为什么 §29 的修复路径在这里是堵死的(量化)

走廊宽度实测(缩放页坐标,θ 周期):

| | res 41 | res 61 |
|---|---|---|
| 种子区域 ↔ rest 类最近距离 | **1.79 格对角线** | **1.79 格对角线** |
| 位置 | θ=−2.9845, y=0.500 | θ=+3.0369, y=0.583 |
| 失败 y 带 [0.57,0.66] 内 | 2.41 | 1.79 |

两个分辨率都是 **1.79**,所以这是真实几何,不是网格噪声;而且它**就在 θ 接缝上**,
正是失败所在。走廊宽 0.100 缩放单位(res 41),而回灌守卫
`feedback_margin = 1.0 格对角线 = 0.0559` **在两侧各占 0.0559**:
`0.100 − 2×0.0559 < 0` —— **守卫比它要穿的走廊还宽**。
这就是 §29 两难的定量形式,也解释了为什么 §4 表里所有旋钮都无效。

## 7. 因此正解是**精确两侧边界锚点**,不是虚拟障碍

SVM 是最大间隔分类器:**把两类的真实边界都喂给它,零集自然落在走廊正中**
(走廊宽 0.100 ⇒ 两侧各 0.050,面的包围球放得下)。现在它只看到网格格,
离真实边界最远可达一整格,于是"它以为的走廊"本身就是错位的。

机制与 §32 / 不变量 18 的 `edge_anchor_samples` 同源(那条补的是 **y** 边),
这里补的是**有效集在 θ 接缝上的边界**:对每一对"区域内有效格 / 相邻非区域格",
沿连线二分 `classify()`,取有效一侧的点。**是精确姿态,不是编出来的障碍**,
且**只进训练集**(不变量 18)。

## 14. 运行时间:为什么是 ~95 s,以及**能**和**不能**怎么提速

### 14.1 时间花在哪(实测墙钟,不是 cProfile)

EXP 5a′ res 81:stage 1+2 **2.0 s**,`run_proof` **98.8 s**,出图 1.5,GIF 10.1。

| 组件 | 调用 | s | 占 `run_proof` |
|---|---|---|---|
| **SVM 拟合 `train_wall`** | 11 | **84.6** | **91%** |
| └ 其中由 Alg 2 回灌触发的重训 | 9 | 69.6 | 75% |
| Alg 2 本身(不含重训) | 3 | 0.53 | 0.6% |
| 重建零集 | 3 | 5.29 | 5.5% |
| **精确边界锚点**(二分 `classify`) | 2 | **1.60** | **1.7%** |
| Alg 3 逐面验证 | 3 | 1.23 | 1.3% |

**与 EXP 5b(§37o)完全相反**:5b 是拟合 1.8%、重建 36%、验证 53%。
`CLAUDE.md` 里"学墙几乎不要钱,贵的是重建与验证"**只对 5b 成立,对锚点配置不成立**。

### 14.2 根因:γ 阶梯

`train_wall` 从 `gamma_init=1.0` 以 `gamma_step=0.1` 往上爬,**每一级都做一次完整
`SVC.fit` 再做一次完整 `.score()`**,直到训练精度 = 1。本场景 γ 要爬到 11.5–19.7,
即**每次调用约 106–188 级**。

```
SVC.fit 总调用 1187 次,50.9 s(55%);训练集 5696 点;平均 43 ms/次
.score() 每级还要 41.9 ms —— 和拟合本身几乎一样贵
```

**EXP 5b 为什么 8 s**:它的 γ = 1.0 = `gamma_init`,**第一级就分开了,只拟合一次**。

### 14.3 单次拟合为什么 ~50 ms(四项实测)

| 因素 | 实测 | 结论 |
|---|---|---|
| 规模 | n=617→1.8 ms,1235→5.2,2470→15.5,4940→56.2 | **≈ n^1.8,主因**;锚点把 n 从 1060 抬到 4940 |
| 核缓存 | 40/200/1000/4000 MB 全是 **51 ms** | **无影响,我的"缓存颠簸"假设是错的** |
| γ | γ=1.0 → 458 SV / 50.8 ms;γ=11.5 → 168 SV / 31.4 ms | **低 γ 最慢,而阶梯偏偏从低 γ 起步** |
| tol | 1e-3 → 5e-2 几乎无变化 | 无关 |

### 14.4 折叠线门的贡献:**13% 的点、19% 的时间,但不影响 γ**

252 个 Σ 圆盘全部来自折叠线,给种子类贡献 **756 点**(占训练集 13%)。
去掉它们(仅诊断,不变量 7 不允许):γ **不变**(11.5,106 级),时间 7.61 → 6.15 s。
**γ 由另一对点决定**:y=0.700、θ=+3.1177(种子)与 θ=−3.1177(其余),
跨 θ 接缝相距 0.0152 —— **又是接缝,不是折叠线**。

### 14.5 IJRR 的方法**不能**用来提速

* IJRR 让流形进 `C_obs` 的手段就是**在边界附近多采点**,而我们的代价 ∝ n^1.8 ——
  **这正是费时的那一项**。我们的精确锚点已经是同一想法的廉价版:
  在边界**上**放一个点,抵得上向边界**逼近**的许多采样点。
* IJRR 自己的瓶颈是三角化(他们 80% 的时间),**我们 d=2 退化为等值线追踪,只占 5.5%**。
* 他们的并行(`#pragma parallel for` 在 Alg 2 / Alg 3)对应我们 0.53 s 与 1.23 s,
  **完美并行也只省 ~2%**。
* **我们的瓶颈恰恰是他们的 Algorithm 1,连常数都是论文原值**(γ=1.0, Δγ=0.1)。

### 14.6 **锚点稀疏化:已撤回,分辨率上不稳**

| 变体 | 面 | 闭合 | γ | 时间 | 是证书? |
|---|---|---|---|---|---|
| dens 8(基线) | 301/301 | True | 19.7 | **94.9 s** | **是** |
| 每 3 个取 1,res 81 | 307/307 | True | 32.6 | **33.3 s** | 是 |
| 每 3 个取 1,**res 61** | 158/161 | **False** | **236.1** | **1202.7 s** | **否** |
| 每 3 个取 1,res 101 | 416/417 | True | 11.4 | 78.7 s | 否(1 个 depth limit) |
| 每 4 个取 1(iters 16/24/32、guard 0.10 四组**完全相同**) | 420/421 | True | 13.6 | 37–56 s | 否 |
| dens 2 | 395/396 | True | 9.0 | 83.7 s | 否 |
| **只在 y∈[0.40,0.90] 放锚点** | 160/162 | **False** | **294.6** | **888.9 s** | **否** |

**两条教训:**
1. **覆盖面要全,密度可以低。** 空间上截断锚点会让训练集难分、γ 炸到 294.6、慢 9×。
2. **但稀疏化在分辨率之间不稳**:同一个"每 3 取 1"在 res 81 是 3× 加速的完整证书,
   在 res 61 是 20 分钟的失败。**不可上线**,保持 dens 8。

### 14.7 **真正安全的两个提速(未实现)**

| 手段 | 预计 | 会改变结果吗 |
|---|---|---|
| **Alg 4 提前退出**:墙与训练集都不再变化时停 | **~30%** | **不会**。实测 iters 16/24/32 **都是 6 次拟合、同一面墙**,却分别耗 37.1/46.8/55.6 s —— 每多一轮白跑一次 `check_polytope`,约 1.2 s |
| **把 `.score()` 换成项目自己的 numpy 判别式** | **~45% 的拟合时间** | **不会**。§17 已验证与 sklearn 差 1.5e-11 |
| 几何 γ 阶梯(106 级 → ~11) | ~10× | **会**,选出的 γ 变了 ⇒ 必须重跑全部实验核对面数 |

前两项纯属去掉浪费,**不改变选出的 γ、不改变墙、不改变任何面的判定**,
合起来应能把 ~95 s 压到 35–40 s 而证书仍是 301/301。
