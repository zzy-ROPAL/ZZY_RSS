## Q1. EXP 2 / EXP 3 为什么慢?所有可能的原因

### 先说结论:**证明本身不慢,慢的是别的东西**

测量时的状态(改动之前):

```
EXP 2 总计 12.1 s                    EXP 3 总计 45.4 s
  八页图 + Σ + 16 道门纤维  4.2 s      八页图 + Σ + 门纤维       4.5 s
  prove()  ← 真正的证明    1.6 s      墙 #1(只为出图)         4.1 s
  出图                     ~2 s       墙 #2(只为出图)         1.5 s
  出视频                   ~4 s       run_proof ← 真正的证明    6.3 s
                                      出图                     1.2 s
                                      出视频                  27.7 s  ← 61%
```

本次把 Q7 的八页共享构建和 Q4 的填缝都做了之后(全部 100% 覆盖、全部闭合、
EXP 3 仍 `proven=True`):

| | 改之前 | **改之后** |
|---|---|---|
| EXP 1 总计 | ~21 s | **11.2 s** |
| EXP 2 总计 | 12.1 s | **8.3 s** |
| EXP 2 的墙 | 147/147,1.56 s | **145/145,0.64 s** |
| EXP 3 八页图 + 门纤维 | 4.5 s | **1.3 s** |
| EXP 3 墙 #1 / #2 | 4.1 / 1.5 s | **1.7 / 1.2 s** |
| EXP 3 `run_proof`(真正的判定) | 6.3 s | **1.5 s** |
| EXP 3 出视频 | 27.7 s | 27.6 s(没动) |
| EXP 3 总计 | 45.4 s | **34.6 s** |

**EXP 3 的全部计算(八页图 + 两面墙 + 两页的 run_proof)现在是 5.7 秒,
只判定的话 2.8 秒;出视频 27.6 秒,占 EXP 3 的 80%。**

**EXP 2 的完整 IJRR 证明(Alg 1–4,147/147 面,闭合)只要 1.56 秒。**
你说"2-D 任务不可行性应该几秒内结束"——**它已经是了**。
EXP 3 的真正判定(`run_proof`,两页两面墙,276/276 + 281/281)是 **6.3 秒**。

### 关于"是不是 IK 太慢"

实测单次代价:

| 调用 | 时间 |
|---|---|
| `arm.ik_branch` | **72.7 µs** |
| `arm.frames` | 16.9 µs |
| `scene.check` | 60.5 µs |
| `classify`(= 上面三个 + 开销) | **187 µs** |
| `arm.jacobian`(有限差分,14 次 FK) | **289 µs** |

`prove()` 的 1.56 s 里 `ik_branch` 被调用 3440 次,累计 **0.564 s**。
所以 IK **是**单位成本的主项,但证明一共只需要三千多次 IK —— 半秒。
**不是 IK 让它慢的。** 真正吃时间的是下面这些,按实测占比排序:

### 原因清单(按实测代价排序)

**1. 出视频 —— EXP 3 的 61%(27.7 s / 45.4 s)**
matplotlib 逐帧画 3D 场景 + ffmpeg 编码。和证明零关系。
`run_three.py --only 3` 里把 `exp3_video` 去掉,EXP 3 立刻从 45.4 s 变成 ~17 s。

**2. 同一面墙建了两遍 —— EXP 3 的 12%(5.6 s)**
`exp3_wall1`(4.1 s)+ `exp3_wall2`(1.5 s)是**专门为出图和视频**手搭的两面墙;
紧接着 `run_proof`(6.3 s)在同样两个区域上**又建了一遍**。
`run_three.py:920` 的注释自己也写明了这一点。把 `run_proof` 返回的
`certificate` 里的墙拿去画图,直接省掉 5.6 s。

**3. 八页网格 —— EXP 2 的 31%(3.8 s)**
`build_page_map` 是纯 Python 双层循环,8 页 × 3721 格 = **29 768 次**
(IK + FK + 碰撞)。这一项**已经修掉了**:见 Q7,现在 0.80 s(4.5×,逐格 bit 相同)。

**4. `reconstruct_wall` 在 281×421 的稠密网格上重算 SVM —— `prove()` 的 44%**
cProfile:`reconstruct_wall` 两次调用 0.682 s,几乎全在 `WallModel.decision`
(1642 次调用 0.660 s)。每次重建都要在 **118 301** 个网格点上求 RBF 判别式,
然后让 matplotlib 做 marching squares。而 Algorithm 4 每轮最多调它两次,
`iters` 最多 14 轮。
**这是算法选择问题,不是语言问题**:零集是一条曲线,用预测-校正的曲线追踪
(从一个零点出发,沿切向走、法向投影)只需要 O(n) 次求值,而不是 O(n²)。
教授的代码正是这么做的(Gudhi `manifold_tracing_algorithm`),见 Q2。

**5. `_pd_lipschitz` 用有限差分雅可比 —— `prove()` 的 24%**
`y_plus_penetration` 0.537 s,其中 `_pd_lipschitz` 0.448 s,
其中 `_fd_jac` **0.382 s**。每个面心要算两个 Lipschitz 常数
(`_jac_norm_q`、`_jac_norm_workspace`),每个都是 2 维有限差分 ⇒ 4 次
额外的 IK+FK+碰撞。LWA 4D 的解析雅可比是写得出来的,这 0.38 s 可以变成 ~0.02 s。

**6. 整个代码是标量 Python**
`ik_branch` 做的是三十来行 numpy 标量运算却要 72.7 µs —— 其中绝大部分是
解释器与 numpy 的逐次调用开销(每个 `np.cross`、`np.linalg.norm` 都是一次
Python→C 往返;profile 里 `numpy.cross` 6880 次占 0.259 s,
`normalize_axis_tuple` 42 346 次占 0.105 s,这些是**纯开销**)。
同样的数学在 C++ 里是 ~1 µs 量级。
**但注意**:这只影响那 0.56 s,把它变成 0.01 s,`prove()` 从 1.56 s 变 1.0 s。

**7. 完全没有并行**
三处天然可并行,现在全是串行:
- Algorithm 2 的 160 个投影(彼此独立)
- Algorithm 3 的 147 个面检查(彼此独立)
- 八页网格(彼此独立)
教授的代码对这三件事各开一个 `boost::asio::thread_pool(hardware_concurrency())`
(`InfPlanner.cpp:1375, 1899, 2126`)。4 核上理论 ~3.5×。

**8. 网格代价是 res^d,这是墙而不是常数**
res 61、d=2 是 3721 格;d=3(IROS 的 2D 曲面任务)就是 226 981 格。
`run_sampled.py` 已经把这条路让给 PRM 了(§25),但 `find_coord_discs`、
`find_kin_discs` 仍在读网格(待办 6)。

**9. sklearn 的 SVM 训练:现在只占 3%**
`train_wall` 0.043 s。§17 已经把这块从 99.3% 打下来了,不用再动。

### 所以要不要上 C++ + 并行?

**要,但顺序必须是这样**,否则是在优化错的地方:

| 顺序 | 做什么 | 预计 | 为什么先做 |
|---|---|---|---|
| 1 | 出视频改成可选(`--no-video`) | EXP 3 45 s → **17 s** | 一行参数,2.6× |
| 2 | 图复用 `run_proof` 的墙 | 17 s → **11 s** | 删代码,不加代码 |
| 3 | ~~八页共享 IK/碰撞~~ **已完成** | 3.8 s → **0.80 s** | 见 Q7 |
| 4 | `reconstruct_wall` 换曲线追踪 | `prove()` −40% | 算法改进,Python 里就能做 |
| 5 | 解析雅可比 | `prove()` −20% | 数学改进,Python 里就能做 |
| 6 | Alg 2 / Alg 3 多进程 | −60%(4 核) | `multiprocessing.Pool`,~50 行 |
| 7 | **才轮到 C++** | 剩余部分 ~20–50× | 见 Q2 |

第 3 条已完成(Q7),Q4 的填缝顺带把 4、5 的一部分收益提前拿到了
(`run_proof` 6.3 s → 1.5 s)。把 1、2 做完,EXP 3 全流程大概 **7 秒**;
再做 4–6,证明本身进入**亚秒**。
**那时候再谈 C++,是为了 d=3 和真实 STL 网格,不是为了这个 2-D 演示。**

## Q2. 教授的 `InfPlanner.cpp` 能用上什么;要不要整体改 C++

### 这份代码是什么

`InfPlannerPRM` 是 Li & Dantam 的 IJRR 方法在 OMPL 里的实现(基于 OMPL 的
`PRM`)。4512 行。关键结构:

```
solve()                                   InfPlanner.cpp:769
 ├─ constructRoadmap(...)                  主线程:长路图
 ├─ std::thread slnThread   → checkForSolution()    找解
 ├─ std::thread SDCLThread  → generateSamples()     学墙 + 采墙
 └─ std::thread infThread   → checkManifold()       三角化 + 查面
```
三条线程 + 一个共享的 `manifoldMutex_`,**anytime**:谁先成功谁结束
(`ptcOrSolutionFoundOrInf`)。

| 它的部件 | 在哪 | 对应我们的 |
|---|---|---|
| ThunderSVM(`SVC`,`param_.gamma=1.0`,`C=100`) | 3561 | `train_wall`(sklearn) |
| nlopt 投影到墙(`objfunc2/3` 带解析梯度) | 172 | `project_to_wall`(我们已换成闭式 Newton) |
| **Gudhi Coxeter 三角化 + 流形追踪** | 1830 | `reconstruct_wall`(matplotlib contour) |
| `manifold_tracing_algorithm_par_libcuckoo` | 1856 | — |
| `construct_n_save_simplices_par` → 线程池 | 1891 | — |
| `checkSimplices` → 线程池(`num_threads*2`) | 2107 | `check_polytope`(串行) |
| `checkSimplex2D` | 2260 | `check_facet` |
| `triangulationLocalFix` | 2004 | Algorithm 4 的"重建失败"分支 |
| `lambda_ *= 0.9` 自适应细化 | 1284 | `net_d_min *= 0.5` |
| `makeTrainingDataFromGraph`(按连通分量定类) | 3631 | `RoadmapLabeller`(§21/§25 已搬过来) |

### 值得搬的三件事(按价值排序)

**1. 三条并发线程的 anytime 结构** —— 这是方法层面的东西,不是实现细节。
我们现在是"先建八页图 → 再建墙 → 再查面",一条直线。它是
"一边长路图一边学墙一边查面,谁先赢谁结束"。对**可行**的场景(EXP 1、将来的
EXP 4)这个差别很大:路图线程可能 0.5 s 就找到解,根本不用等墙。
Python 里用 `threading`(GIL 会挡住 numpy 外的部分)或 `multiprocessing`
都能做,**不需要 C++**。

**2. 线程池并行化 Alg 2 / Alg 3** —— 见 Q1 第 7 条。

**3. `checkSimplex2D` 的做法值得注意**(`InfPlanner.cpp:2260`):
d=2 时她**根本不算穿透深度**。面(线段)的检查就是
OMPL 的离散运动检查——两端点若 valid 直接 `addToTraining` 返回失败,否则
按 `validSegmentCount` 递归二分取中点查 valid。
我们的 `check_facet` 算 `pd` 再和最小包围球半径 `r` 比。
两者都对,但她的版本**不需要 Lipschitz 常数**,也就没有 §19 里那个
"`_pd_lipschitz` 返回 raw units 而 `radius` 是 scaled units"的隐患,
而且便宜得多(省掉 Q1 第 5 条的 24%)。
**代价**:她的版本只能说"这条线段上采到的点都无效",不是"这条线段整体在
`C_obs` 内"——严格性靠 `validSegmentCount` 的分辨率,而我们的 `pd ≥ r` 是
**真的覆盖整段**。所以这是**严格性换速度**,不要盲目换;
但可以作为**预筛**:先跑便宜的离散检查,只对通过的面再算 `pd`。

### 不值得搬的

- **Gudhi Coxeter 三角化**:在 d=2 完全是浪费。IJRR §4.3 的切向 Delaunay 复形
  在 d=2 退化为"把零集连成折线",我们的 `reconstruct_wall` 已经直接给出有序
  折线并顺带验证闭合性。她自己的代码里 `if (si_->getStateDimension() == 2)`
  有专门的 2-D 分支(`save2DRNtriangulation`、`checkSimplex2D`)。
  **真正需要 Gudhi 的是待办 8(d=3,IROS 的 2D 曲面任务)** —— 那时候
  三角化才是主要开销,也才是她 >90% 时间花的地方。
  值得搬的其实是她的**流形追踪**思想(Q1 第 4 条),这个 Python 里就能实现。
- **ThunderSVM**:我们的 SVM 训练占 3%。换 GPU SVM 省不到 0.05 s。
  顺便注意:她的 `trainingSetup()` 把 `gamma` **固定在 1.0**、`C=100`,
  Algorithm 1 的 γ 递增循环在她代码里是**注释掉的**(3579–3588 行)。
  我们的 §29 讨论的 γ 上限问题,在她的实现里根本不存在,因为她不递增 γ。
  这点在汇报时值得提:**我们比发布的实现更贴近论文的 Algorithm 1。**
- **OMPL / amino / libcuckoo / boost::asio 这一整套依赖**:
  要让它跑起来得装 OMPL、Gudhi、ThunderSVM(CUDA)、nlopt、amino、
  libcuckoo、Eigen、boost。这是几天的构建工作,换来的是上面那三件
  我们在 Python 里也能做的事。

### 要不要把我们的代码整体改写成 C++

**我的建议:现在不要。** 理由是 Q1 的实测:

- 证明本身 1.6 s / 6.3 s。C++ 把它变成 0.1 s / 0.4 s,**没有改变任何能做的实验**。
- 占 61% 的是**视频渲染**,C++ 不会让 matplotlib 变快。
- 真正要上 C++ 的触发条件是**待办 8:d=3**。那时候网格彻底不能用、
  三角化变成主开销、碰撞检测要换真实 STL 网格(FCL),
  那是 C++ + OMPL + Gudhi + FCL 的主场。
- 而且现在改 C++ 会**冻结正在动的东西**:碰撞几何还是胶囊近似(待办 4),
  EXP 4 的场景还在搜(Q3),证书校验器还没写(待办 3)。
  用 Python 探索、定稿后再移植,成本低得多。

**折中方案(如果确实想要 C++ 的速度)**:把**叶子函数**移到 C++,主流程留在
Python。只需要三个函数:`ik_branch`、`frames`、`scene.check` —— 加起来
150 µs/次,占了所有标量开销。用 pybind11 包一个 `_fastkin` 扩展,
再加上 `decision`(RBF 判别式,纯算术)。四个函数、约 400 行 C++,
**不碰任何算法逻辑**,预计把 `prove()` 从 1.56 s 压到 ~0.5 s,
并且 d=3 时这四个函数仍然是热点,投资不会白费。这是我推荐的路。

## Q3. EXP 4:起始页无解 → 过奇异 → 新页有解

### 这个实验已经有脚本了,而且失败原因已经定位

`scripts/run_e4.py` 就是这个实验("forced sign change"),§16 记录了它为什么
没成:要让"走完焊缝必须中途换符号",需要 **q6 门** + **s6 不对称**同时成立,
而在扫过的摆放里,产生不对称的区域(肘部高位,θ≈±π)和 q6 门自己的肘部位置
重合——任何造出不对称的障碍都同时关掉了门。

### 这次新测出来的东西:**q6 门是物理上真能走的,q2 门永远不能**

§30 记录的是 EXP 3 的门只在"保守意义"上开(伙伴页代表元 |q1|=180°,
超真机限位 1.15°)。这个结论**只对 q2 门成立**。实测:

```
                  门类型      y      theta  |     q1      q3      q5      q7 | 伙伴页在限位内
x0.28 z0.46 tilt  0    q2   0.1943  +0.0000 |   0.00  -29.59 -180.00  -29.59 | 否(差 1.15°)
x0.32 z0.40 tilt 15    q2   0.3356  -0.0000 |   0.00  -15.97 -175.27  -17.84 | 否(差 1.15°)
x0.50 z0.30 tilt 60    q6   0.2537  +0.3540 | -40.69   34.38   34.87  121.32 | **是**
x0.50 z0.30 tilt 60    q6   0.7463  -0.3540 |  40.69  -34.38  -34.87 -121.32 | **是**
x0.55 z0.25 tilt 60    q6   0.2098  +0.4212 | -37.19   32.30   43.12  108.30 | **是**
x0.55 z0.25 tilt 60    q6   0.7902  -0.4212 |  37.19  -32.30  -13.19 -141.25 | **是**
```

机制(接 §31 的余量表):

| 门 | 镜像动的关节 | 需要的余量 | 实际余量 |
|---|---|---|---|
| **q2** | q1, q2, q3 | \|q1\| ≥ 1.15°,\|q3\| ≥ 1.15° | **q1 恒为 0**(门恒在 θ=0 ⇒ 必败) |
| **q6** | q5, q6, q7 | \|q5\| ≥ 1.15°,\|q7\| ≥ 11.55° | q5 ≈ 35°,q7 ≈ 121° ⇒ **过** |

**q2 门必败是结构性的**(§12:`q2=0` 把肘部钉在关节 1 轴上,而臂角参考平面
正由该轴构造 ⇒ 门精确落在 θ=0 ⇒ q1=0)。
**q6 门没有这个约束**,门落在 θ=±0.354(不是 0),q1 = ∓40.69°,
三个被镜像平移的关节全都离 ±180° 很远。

### 所以 EXP 4 的规格应该是

1. **门用 q6 门,不要用 q2 门。** 焊缝摆放用 `run_e4.py` 已经找到的
   x=0.50, z=0.30, 倾角 60°(或 x=0.55, z=0.25, 60°)。
   `search_scene.py --mode welds` 可以继续扫。
2. **目标不是不可行,是"只有换页才可行"。** `flood.run_proof` 已经支持:
   它在目标被达到时返回 `proven=False`。EXP 4 的判定就是
   `run_proof` 在起始页建起一面闭合墙(起始分量到不了终点)、
   走一道 **q6 门** 到伙伴页、在伙伴页**到达终点** ⇒ `proven=False`,
   证书里带一面墙 + 一道门 + 一条伙伴页上的路径。
3. **剩下的工作是场景搜索**:要一个障碍使 `s6=+` 页的起始分量到不了终点、
   而 `s6=−` 页能到,且 q6 门开着。§16 记录了第一轮没搜到,
   新信息是**门的 θ 位置已经知道了(±0.354)**,
   §31 的余量表也给出了不对称的来源(q7 余量 11.55°,凡 |q7| < 11.55°
   的格子翻 s6 就越限)。所以搜索可以从"**找一个障碍,让 s6=+ 页在
   θ 远离 ±0.354 的地方断开**"这个明确判据出发,而不是盲扫。

这一条我**没有实现**,因为它是一次需要收敛的场景搜索(§16 的第一轮扫了
4 维 48+ 个摆放),不是一次改代码。上面是规格;要我接着搜,说一声。

## Q4. EXP 2 采样流水线的失败:按论文的"虚拟障碍"办法修

### 失败是什么

`run_sampled.py`(PRM 驱动,网格只画图)的 EXP 2 墙只有 **111/122 面**,
γ 顶在上限 30,**失败面全部聚集在页左边缘 y≈0**。

### 为什么

论文 IJRR Fig. 5 的虚拟障碍技巧有**两半**,我们只实现了一半:

| Fig. 5 的两半 | 我们的实现 | 状态 |
|---|---|---|
| 页外是**正厚度的虚拟障碍带** | `in_virtual_invalid`(ε=0.03) | ✅ |
| 带外再包一圈**虚拟自由区**,喂进对面那一类 | `virtual_boundary_samples` | ✅ |
| **本页一侧 y=0 处起始类自己的训练点** | 网格流水线白拿(y=0 那一行);采样流水线**没有** | ❌ |

虚拟圈只告诉墙"页外面是另一类",**没有告诉墙起始区域到哪里为止**。
这是两件不同的事。网格流水线里 y=0 这一行格子天然在训练集里,所以墙知道
左边界;随机路图几乎不采到 y=0,墙就不知道左边界在哪,于是**在页内部就把
有效起始区切掉了**——这正是所有失败面都在 y≈0 的原因。

### 修法

`src/zzy_rss/wall.py` 新增 `edge_anchor_samples()`:**精确扫出 y=y_min 与
y=y_max 两条边线上所有有效的臂角**,喂进 **SVM 训练集**(不是路图)。
每个锚点按它**连通到哪一分量**定类(`RoadmapLabeller`,就是 SDCL 的
`addToTraining` 规则),所以锚点不可能和路图自己的分量矛盾。

**关键区分(不变量 18)**:这些点只能进**训练集**,不能进**路图**。
把它们插进路图会把图顶点放到边界带上,墙从此无法贴着带闭合
(实测 111/122 closed 变成 132/152 **开环**)。`run_sampled.py:357` 的注释
记录了那次尝试;本次改动刻意走的是另一条路。

同时修第二件事:`run_sampled.py` 的 `--gamma-max` 默认值是 **30**,而
§29/不变量 14 已经论证过"30 是 IJRR 自己单位里的数字",在我们的页尺度
(两类最近点相距 0.060)下 γ=30 是**很宽的核**,把难页钉成不可分
(accuracy 0.95 < 1,墙连自己的训练数据都分不开)。网格流水线在 §29 已经
抬到 400,采样流水线被漏掉了、从未重测。现在也改成 400。

```
scripts/run_sampled.py --samples 1500 --only exp2     # 默认开启
scripts/run_sampled.py --no-edge-anchors              # 关掉做对照
```

### 还有第三件事:带与环之间有一条缝

加上锚点之后失败面确实离开了页内部,但**全部移到了 y ≈ −0.055**。
那里原来是个"既不是带也不是环"的缝:

```
虚拟环      y_min − 2ε = −0.060      ← 对面那一类
虚拟障碍带   (y_min − ε, y_min) = (−0.030, 0)   ← check_facet 直接放行
缝          (−0.060, −0.030)         ← 两者都不是
```

墙落进那条缝时,`in_virtual_invalid` 说"不在带里",`classify` 去算
y=−0.055 的位姿——焊缝线性外推那一点**往往还是有效的**——于是报
`facet centre is VALID`。新增两个参数把缝填掉:

```python
virtual_band_outer: float = 2.0   # 带的外沿(virtual_band 的倍数)
virtual_ring:       float = 2.5   # 环的位置,必须 > virtual_band_outer
```

这不是放宽标准:`y < y_min` 是焊缝之外,任务在那里根本没有定义,
没有任何路径可以经过;带的厚度是建模选择,只需为正且不含虚拟自由环。

## Q5. 门是一条线(q4 奇异)时怎么证?

### 先澄清"点门"和"线门"的对偶关系

这是本次最有意思的一个发现。两种门在**页坐标**里和在**构型空间**里恰好对偶:

| | 在页 `(y, θ)` 里 | 在构型空间 `Q` 里 | 沿门机器人动不动 |
|---|---|---|---|
| **q2 / q6 门** | 一个**点** | 一条**线**(自运动纤维) | 不动(§30:万向节零运动) |
| **q4 折叠门** | 一条**线**(该 y 处整条 θ) | 一个**点** | 不动(实测肘部位移 0.43 mm) |

`doors.py:find_fold_doors` 已经按"线门"实现了:它在折叠处的 y 上
**沿整个 θ 范围铺一排圆盘**,注释也写明"the elbow circle collapses,
the arm angle loses meaning, and the WHOLE theta-line at that y degenerates
to one configuration"。

实测验证(x=0.60, z=0.40, 倾角 15°,折叠点 y\*=0.15850499):

```
在折叠点 (y*+1e-6),θ 扫一整圈,各连杆点的最大位移:
   shoulder 0.000e+00 m   elbow 4.299e-04 m   wrist 1.010e-13 m   tool 1.011e-13 m
对比:离折叠点 0.05 处同样扫一圈
   shoulder 0.000e+00 m   elbow 9.251e-02 m   wrist 3.724e-16 m   tool 3.724e-16 m
```

肘部从 92.5 mm 的摆动缩成 **0.43 mm** —— 整条 θ 线是**同一个姿态**,
手臂伸直、绕自己的 S→W 轴"自转",占据的体积不变,变的只有关节值。
所以**沿折叠线的有效性是纯限位问题,碰撞状态恒定**(和 §30 的 q2 纤维同一个机制)。

### 实际的好消息:线门的限位比点门宽松得多

点门只有**一个** `(y, θ)` 可选,它的镜像代表元在不在限位内是**没得挑的**
—— §30 的 1.15° 就是这么丢掉的。
线门有**整条 θ** 可选,只要**有一个** θ 的两个 s4 代表元都在限位内,门就是开的。实测:

```
y = y*+1e-6 :  s4=+ IK 361/361,在限位 355/361,最佳余量 0.374 rad (21.4°)
               s4=- IK 361/361,在限位 356/361,最佳余量 0.374 rad (21.4°)
```

**21.4° 的余量**,对比 q2 门的 **−1.15°**。而且 `q4 = ±0.076°`:两页在折叠点
真的合并了。**穿过去就是经典的"肘部翻转"(elbow flip),手臂伸直再继续,
物理上完全可执行。**

### 坏消息:在我们这个任务里,q4 折叠门**不可能落在任务内部**

这是一个可以证明的结论,不是搜索没收敛:

> 直焊缝 + 固定工具姿态 ⇒ `W(y) = p0 + y·(p1−p0) − d_wt·(R e_z)` 是 y 的**仿射**函数
> ⇒ `|W(y) − S|` 是 y 的**凸**函数
> ⇒ `{y : |W−S| ≤ reach_max}` 是**一个区间**
> ⇒ `|W−S| = reach_max`(即 q4 折叠)只能落在这个区间的**端点**上,
>   也就是任务**离开工作空间**的地方。

扫 2280 个焊缝摆放实测:**非凸的 0 个,可达集不是单区间的 0 个。**
而 EXP 1/2 的焊缝 `|W−S| ∈ [0.4121, 0.4873]`,EXP 3 的也类似,
离 `reach_max = 0.6510` 很远 —— **现在的三个案例里根本没有 q4 门**。
`reach_min = |d_se − d_ew| = 0.0050 m`(腕心要摸到肩部 5 mm 内),实际不可能。

### 要一条内部的线门,怎么办

把 `W(y)` 的仿射性打破:

- **弯焊缝(圆弧焊缝)** —— 最自然,工业上也最常见。实测一个 R=0.18、
  圆心 (0.50, 0.36) 的圆弧缝:`|W−S| ∈ [0.3356, 0.6810]`,
  二阶差分最小 −6.6e-6 < 0(**非凸**),并且**跨过** `reach_max=0.6510`
  ⇒ 内部折叠门存在。
- **沿缝变化的工具倾角** —— `R` 随 y 变 ⇒ `W(y)` 非仿射,同样可行。

这需要把 `weld.py` 从直线推广到参数曲线(`WeldLine.position(y)` 改成
一般曲线 + `rot(y)`),是一处**局部**改动:`pose()`/`wrist_center()` 是
所有下游代码唯一的入口,`doors.py` 里两处解析二次方程需要换成数值求根。

### 线门在证明里怎么用(算法层面)

假设门确实落在内部的 y\*:

1. **页内不可能绕过它。** 折叠线横跨整个 θ 范围,把页(圆柱)切成
   y<y\* 和 y>y\* 两段。任何分开起点和终点的闭合墙**必须**穿过这条线,
   而 `check_facet` 的 Σ 守卫(`segment_hits_disc`)会直接拒绝。
   ⇒ **起点和终点分居折叠线两侧时,单页内的不可行性证明是不存在的**,
   泛洪**必须**走门。这比 EXP 3 的点门更强:点门可以被墙围在里面,线门不行。
2. **门的认证却比点门更便宜、而且是精确的。** 整条线是**一个**物理构型,
   所以只要查**一个**构型的碰撞 + 两个 s4 代表元的限位,
   不需要 §5 待办里担心的"纤维是零测集、采样只是证据"——
   折叠门没有纤维要采,它就是一个点。**待办 5 对线门自动解决。**
3. **墙的形状变了**:证明变成"在 y<y\* 这一段里,起始区域被一面闭合墙围住,
   且这面墙把折叠线上的有效点也围在里面"——也就是折叠线成了 `seed` 类的
   一部分(和 `sigma_disc_samples` 现在对点门做的事一样,只是圆盘变成一排)。
   `find_fold_doors` 铺出的那一排圆盘已经是这个形状,代码不用改。

## Q6. "先每页各证一遍,再用 SVM 符号判断门在墙内外"

你的提法是:八页各自建好不可行性证明;然后看门的位置,如果门落在
分开起点和终点的那面墙**里面**,就用 SVM 判别式的符号判断
(`sign(door) == sign(start)` ⇒ 同侧),这样机器人换页时**不需要重做证明**。

### 对的部分(而且已经在代码里了)

**用 SVM 符号判断门在墙内外,是对的。** 墙是 `f=0` 的零集,
`reconstruct_wall` 已经验证它是**一条闭曲线**,所以 `sign(f)` 就是内外。
而且**门是圆盘不是点**,整个圆盘都必须在同一侧——
这一条 `check_facet` 的 Σ 守卫(`wall.py:778`,`segment_hits_disc`)
已经在强制了:墙不许穿过任何圆盘。两者合起来,
查圆心的符号就**足够**判定整个圆盘在内还是在外。

`flood.run_proof` 现在做的就是这件事的等价形式:
`discs_in_region` 挑出属于当前区域的圆盘,墙必须把它们围住
(`sigma_disc_samples` 把它们喂进 seed 类),然后把门后的区域**入队**。

### 不对的部分:**符号判据的方向反了**

`sign(door) == sign(start)` 意思是门**在墙里**,也就是机器人**能走到门**。
那就**必须**给伙伴页那边做证明。
能**省掉**工作的是相反的情况:`sign(door) ≠ sign(start)`,
门在墙外 ⇒ 机器人**到不了**这道门 ⇒ 这道门可以直接丢掉。
这一条代码里也有:`live_discs`(`flood.py:201`)把已认证关闭的门卸掉,
`find_inf_proof_region` 就不用让墙去绕它。

### 更要紧的部分:**"每页预先各证一遍"会把命题换掉**

这正是 §29 第 (c) 条踩过的坑。证明的对象不是**页**,是**(页, 区域)**:

- 一面墙必须围住**某个**起始区域。预先建墙时你不知道泛洪会从门进到
  伙伴页的**哪个**区域,只能选一个播种范围。
- §29 原来选的是"八页上所有碰到 y=0 的区域"。那证的是一个**更强**的命题
  (每个碰到 y=0 的区域都围得住),而且**要求给机器人根本到不了的区域建墙**。
  实测代价:同一区域 γ 从 1.3 顶到 **323–334**,伙伴页的墙建不起来。
- 改成 `seeds=[(START_PAGE, kA)]`(起点是一个位姿)之后,
  EXP 3 的两面墙 3.0 s 和 8.3 s 就都建起来了。

所以"预先每页各证一遍"不是省工作,是**把一个能证的命题换成一个更贵、
而且可能根本不成立的命题**。页不是证明的单位,区域才是。
另外页是会被**重复访问**的:EXP 3 的泛洪是 `++-/1 → -+-/2 → ++-/1`,
到达同一页的不同区域要不同的墙。

### 真正能省工作的三个版本

1. **按 `(页, 区域)` 记忆化** —— `run_proof` 的队列已经在做了
   (访问过的区域不再入队)。
2. **用伙伴页的墙做热启动** —— 把已建好的墙的训练集 + γ 作为新区域
   Algorithm 1 的初值。纯速度优化,零可靠性代价。
   EXP 3 实测墙 #2 比墙 #1 快(1.5 s vs 4.1 s),部分就是因为它的区域更简单;
   热启动能把这个差距再拉大。
3. **按对称性复用证书** —— 见 Q7,这是**真正**能把八页变成一页的那条路,
   而且有实测支持。

## Q7. 页的对称性能不能用?**能,而且是本次最大的收获**

### 对称性是什么(§31 的定量版)

八个符号分支是**同一条手臂的八种关节坐标写法**
(`test_branch_geometry_identical`,断言到 3e-16)。直接推论:

- **IK 存在性**只取决于 `|W(y) − S|` 落在圆环内,这是 **y 的性质,和符号无关**;
- **碰撞逐格相同**(§31 实测:忽略限位时八页差异格 0 / 3721);
- 能区分页的**只有关节限位**,而三个镜像恒等式(`test_mirror_identities`,
  断言到 1e-9)给出其余七个关节向量的**闭式解**:
  `s2: q1→q1±π, q2→−q2, q3→q3±π`,`s4`、`s6` 同理错位。

### 用法一:八页的价钱按一页算(**已实现**)

`src/zzy_rss/pagemap.py` 新增 `build_all_pages_shared()`:
每格**一次** IK + 一次 FK + 一次碰撞,然后用镜像恒等式算出八个关节向量,
八页各做一次限位比较。

```
=== EXP 2 场景 ===  逐页 3.638 s   共享 0.804 s   加速 4.5x
  八页逐格 tag 差异:全部 0 / 3721,max|dq4| = 0,max|d margin| = 1.3e-15
=== EXP 3 场景 ===  逐页 3.987 s   共享 0.894 s   加速 4.5x
  八页逐格 tag 差异:全部 0 / 3721
```

**是精确的,不是近似。** 回归测试
`tests/test_ik.py::test_shared_page_build_matches` 在两个场景 × 八页上
逐格断言两种构建方式完全一致。`build_all_pages(..., shared=True)` 现在是默认,
`shared=False` 保留原实现作为测试的对照基准。

为什么是 4.5× 而不是 8×:每格仍要做八次 `limit_margin` 和八次 Python 字典
索引,这部分没省。真要接近 8× 就得把限位检查向量化到整个网格(下一步)。

### 用法二:**一面墙可能证掉八页**(新结果)

既然碰撞和 IK 存在性都与页无关,`C_obs` 只在**限位**那部分依页而异。
把 EXP 2 在 `(++-)` 上建好的那面墙(147/147)**原封不动**拿到另外七页上
重新跑 Algorithm 3,实测:

```
page +++ : 146/147 面通过   {'depth limit; pd=1.082e-05 < r=4.539e-05': 1}
page ++- : 147/147 面通过      ← 它自己的页
page +-+ : 146/147 面通过   {同上那一个面}
page +-- : 147/147 面通过
page -++ : 146/147 面通过   {同上}
page -+- : 147/147 面通过
page --+ : 146/147 面通过   {同上}
page --- : 147/147 面通过
```

**同一面墙在八页上 146–147/147 通过。** 唯一失败的那个面不是"切进有效区",
而是 `pd = 1.08e-5 < r = 4.54e-5` 的擦边(§18 的老问题,一次重训就能推深)。

这面墙为什么能跨页通用,也测出来了 —— 逐面记录它**凭什么**在 `C_obs` 里:

```
  62 面  joint-limit (Lipschitz)     ← 依页
  62 面  collision (workspace PD)    ← 不依页
  23 面  virtual boundary band       ← 不依页
```

58%(85/147)的面靠**与页无关**的理由通过。剩下 42% 靠限位,
而限位在八页之间只在**很窄的带**上不同(§31:翻 s2/s4 只改 60–70 格,
全部落在 |θ| ≤ 0.31;翻 s6 改 340 格,因为 q7 的余量是 11.55°),
所以那 62 个面碰巧在八页上都是越限的。

### 这给出一条可以写进论文的定理

> **命题.** 设墙 W 在页 P 上闭合,且 Algorithm 3 对 W 的**每一个面**
> 都以"碰撞"或"no-IK"或"虚拟边界带"为理由通过(即不依赖任何
> 关节限位)。则 W 在**全部八页**上都是合法的墙。
>
> **证明.** 碰撞与 IK 存在性都是 `(y, θ)` 的函数,与符号分支无关
> (八个分支摆出同一条手臂,`test_branch_geometry_identical`)。
> 故 `W ⊂ C_obs(P)` 的理由逐面地在每一页上同样成立。∎

**可操作性**:这是**可检查的**,不需要新算法——`check_facet` 已经返回
`reason`,只要加一句"所有 reason 都不是 `joint-limit`"就得到一个
**八页通用的证书**。代价是这样的墙更难建(不能借限位无效区),
但一旦建成,八页图上的八面墙塌缩成一面。

### 用法三:门图是 (Z/2)³ 的 Cayley 图

一道 vanishing set 为 `{j}` 的门连接 `s` 和 `σ_j(s)`。三个镜像生成
`(Z/2)³`,所以**页/门图就是 3-维超立方体**,八个顶点、每顶点三条边、
共 12 条边(我们每个摆放数到 16 道门,是因为有些 `j` 在两个 y 上各有一道)。
碰撞集在整个 `(Z/2)³` 作用下**不变**(它根本不依页),
所以**唯一破坏对称性的是限位**。两个直接推论:

- 如果限位是 ±π(理想手臂),八页**完全等价**,整个页/门结构是平凡的,
  不可行性证明退化成单页问题。**`Y⁺` 的页结构完全是限位现象** ——
  这一条本身就值得在论文里讲清楚,它解释了为什么 §16 的 E4 只能靠 `s6`
  (q7 的 11.55° 是八个余量里唯一够大的)。
- 搜索场景时不必扫八页:扫一页的碰撞 + 八张限位掩码,就是全部信息。
